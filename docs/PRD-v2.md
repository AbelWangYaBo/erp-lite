# erp-lite v2 PRD：医疗器械 GMP 合规 + 多角色权限

> v1 Non-goal「多角色权限」正式解封。定位不变：个人自用演示/参考系统，落地 GMP 关键控制点的**系统能力**，不构成合规认证；法规定性口径留给法规/RA，系统只保证「控制点可执行、证据可留存」。

## 1. 行业背景与系统角色

《医疗器械生产质量管理规范》（GMP）对信息化系统的核心诉求可归纳为：**可追溯（批次/记录）、职责分离（岗位权限）、放行受控（检验合格方可使用）、资质受控（供应商审核）、标识唯一（UDI）**。erp-lite v1 已具备的基础恰好是 GMP 关心的证据形态：单据状态机 + 字段级审计留痕 + 操作日志 + 记录不可物理删除。

v2 在此基础上补齐四个控制点 + RBAC。

## 2. v2 范围

### 2.1 批次/批号管理与追溯（GMP 核心控制点）
- 物料增加 `batch_required`（是否启用批次管理，器械原料/成品默认启用）
- 库存流水增加 `batch_no` + `batch_id`；同物料同批次独立计量现存量与移动加权成本（批次级均价，与 v1 物料级并存，批次物料以批次为准）
- 批次记录：来源单据、供应商（原料）、生产工单（成品）、检验状态
- **正反向追溯 API**：输入成品批次 → 展开所用原料批次及供应商（正向可追到源头）；输入原料批次 → 列出流向的所有成品批次（反向召回）；两层均带单据链接
- SO 出库/MO 领料必须指定批次（批次物料），不指定则 400

### 2.2 物料检验放行（GMP 质量控制）
- 采购入库生成批次时检验状态 = `pending`（待检）
- QA 角色录入检验记录（检项、结论、检验人/日期）并判定：`qualified`（合格，可入库使用）/ `rejected`（不合格，隔离，不可领料/出库，可退货）
- **只有 qualified 批次可被 MO 领料、SO 出库**；pending/rejected 批次参与量不计入可用库存
- 成品批次：MO 完工入库默认 `qualified`（可后续由 QA 复判），留检验记录位
- 不合格批次处理：登记处置（退货/销毁），处置后批次关闭

### 2.3 供应商资质管理（GMP 采购控制）
- 供应商（partner type=supplier）可挂资质证照：名称、编号、发证机关、有效期至、扫描件（v2 存文件引用路径即可，不做对象存储）
- **资质过期或无有效资质的供应商，PO 创建/审核时拦截（400）**；预警：距到期 ≤30 天列表标黄
- 演示种子数据含一个资质临期供应商、一个已过期供应商

### 2.4 UDI/DI 标识
- 成品物料增加 `udi_di`（UDI-DI 编码）与 `udi_pi_rule`（PI 组成规则说明，如「批次号」）；非成品不要求
- 成品出库单据展示 UDI-DI + PI（=批号），满足「每件可识别」的最小落地

### 2.5 多账号与角色（RBAC + 演示切换）
- users 增加 `role` 枚举：`admin / purchase / warehouse / production / qa`
- 权限矩阵（后端 deps 强制，前端菜单/按钮联动隐藏）：

| 动作 | admin | purchase | warehouse | production | qa |
|---|---|---|---|---|---|
| 基础数据维护 | ✓ | — | — | — | — |
| 供应商资质维护 | ✓ | ✓(录入) | — | — | ✓(审核) |
| PO 建/改/审/作废 | ✓ | ✓ | — | — | — |
| PO 入库（按 QA 合格批次放行入库） | ✓ | — | ✓ | — | — |
| SO 建/审 | ✓ | ✓ | — | — | — |
| SO 出库 | ✓ | — | ✓ | — | — |
| BOM/MRP | ✓ | — | — | ✓ | — |
| MO 建/下达/领料/完工 | ✓ | — | — | ✓ | — |
| 检验记录录入/批次判定 | ✓ | — | — | — | ✓ |
| 核销/对账 | ✓ | — | — | — | — |
| 审计查询 | ✓ | ✓ | ✓ | ✓ | ✓（各自可查，GMP 记录可及性） |
| 用户管理/角色分配 | ✓ | — | — | — | — |

- 登录返回 role；`GET /api/v1/auth/me` 返回当前身份与权限集
- **演示切换**：种子建 5 个账号（同密码 admin123），前端顶栏一键切换身份（重新登录对应账号），登录页提供演示账号快捷入口
- 所有写操作审计 actor 带角色，操作日志可按角色过滤

## 3. Non-goals（v2 仍不做）

- 电子签名/复核签名（GMP 电子记录高级要求，演示不做）
- 审批工作流引擎（放行即 QA 判定动作，不加审批层）
- 文件对象存储（资质扫描件只存引用路径）
- 不良事件监测、售后、CAPA 等模块
- 多租户、组织架构

## 4. 关键业务规则（增量）

1. 批次物料所有出入库流水必须带批次；非批次物料保持 v1 行为不变
2. 可用量 = qualified 批次现存量之和；MO 领料/SO 出库仅允许从 qualified 扣减
3. 供应商资质校验在 PO create 与 approve 两处都拦（防资质在草稿期间过期）
4. 检验判定/资质审核动作单独留痕（action=inspection/approve_audit），actor 必须是 qa/admin
5. 追溯查询全员可用（qa/warehouse/production/admin），采购可查自己供应商链路
6. v1 已有数据（无批次）继续有效：batch_required 默认关，历史流水 batch_id 为空合法

## 5. 验收标准（v2 DoD）

1. 五账号可登录，角色间动作受限真实生效（越权 403，如 warehouse 建 PO 被拒），前端菜单/按钮按角色显隐
2. 演示链路：purchase 下 PO → qa 检验合格 → warehouse 入库 → production MRP/MO 领料（只能领合格批次）→ 完工入库（成品批次）→ warehouse SO 出库（带 UDI+批号）→ admin 核销
3. 追溯验证：成品批次正查到原料批次+供应商；原料批次反查到成品批次
4. 合规拦截验证：过期供应商下单被拒；pending/rejected 批次领料被拒
5. 检验判定、资质审核留痕可查（含角色）；pytest 全绿；compose/开发环境冒烟通过
